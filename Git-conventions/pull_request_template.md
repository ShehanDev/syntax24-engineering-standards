## Type of Change

* [ ] ✨ `feat`: A new feature
* [ ] 🐛 `fix`: A bug fix
* [ ] ♻️ `refactor`: A code change that neither fixes a bug nor adds a feature
* [ ] 💄 `style`: Code style/formatting changes (whitespace, missing semicolons, etc.)
* [ ] 📝 `docs`: Documentation updates
* [ ] ⚡️ `perf`: A code change that improves performance
* [ ] 🧪 `test`: Adding missing tests or correcting existing tests
* [ ] 🔧 `chore`: Changes to the build process, aux tools, or dependencies

## Branch Integration

* [ ] **Target Branch:** `develop` (for standard features/fixes) OR `main` (for hotfixes only)
* [ ] **Source Branch:** Follows naming convention (e.g., `feat/`, `bugfix/`, `hotfix/`)

## Testing & Verification

* [ ] Unit tests passed locally
* [ ] Integration tests passed locally
* [ ] Manually tested in local environment
* [ ] Verified UI responsiveness / cross-browser compatibility (if applicable)

## Pre-Merge Checklist

* [ ] My PR title follows the Conventional Commits format (e.g., `feat(auth): add Google login`)
* [ ] My code follows the project's style guidelines and passes the linter
* [ ] I have performed a self-review of my own code
* [ ] I have commented my code, particularly in hard-to-understand areas
* [ ] I have updated the documentation accordingly (if applicable)
